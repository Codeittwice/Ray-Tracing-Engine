1. What this project was, and what it needed to become

solar-cooker-rt was a physics-correct Monte Carlo ray tracer with a thin viewer bolted on. It had done real research — panel-angle sweeps, box-receiver flux maps, a finalised two-level CAD design — but it was not an application. Scenes were authored by Python scripts writing JSON. The GUI could browse those files, nudge two sliders per surface, and trace. You could not import a model, delete anything, or save what you edited. Every one of the 94 committed scenes had the sun frozen at the zenith.

The goal: make it usable by a non-technical cooker builder without breaking the JSON/CLI/batch path the research workflow depends on.

Confirmed scope

  • Audience: mixed, leading with non-technical builders; the expert path stays fully working.
  • Sun: keep the existing Pillbox/Buie sunshape and manual DNI. Add the ability to move the sun off zenith. No latitude/longitude, no atmospheric model.
  • Results: optical only — watts, W/m², concentration ratio, flux maps.
  • AI helper: Claude API with the user's own key. Last priority.
  • Deferred: thermal model, geographic sun, weather files, day-integrated energy.

Four findings that shaped the plan

3. Wave 0 — Foundation and safety net

No features. Everything downstream depends on being able to tell a fix from a regression.

Latent bugs fixed

  • BVH::build retained dangling pointers. The early return on an empty surface list sat above the clear() calls, so a rebuild with no surfaces kept stale Surface* that dangle once the old surfaces are freed. Harmless until objects can be deleted at runtime — which is exactly what Wave 3 adds.
  • Two reserve-invariant hazards. BVH::build_recursive and TriangleMesh::build_tri hold a reference to a vector element across recursive emplace_back calls. Only defined because of an up-front reserve. Documented and asserted.
  • Three unguarded null dereferences in Viewer::draw_gui. My original instruction here was wrong — I said to guard with an early return, copying a sibling function. An agent caught that draw_gui owns the ImGui::Begin/End pair, so returning early would unbalance the frame and corrupt rendering. The guards had to be per-block.

The safety net

A golden-flux baseline: four representative scenes traced at a pinned configuration (rng_seed=42, num_threads=1, 20 000 rays) with the results recorded as constants. Single-threaded matters — it makes the tracer's slot-seeding reduce to exactly rng_seed, so the values reproduce across machines.

Alongside them, a runtime filesystem sweep asserting all 94 committed scenes load without throwing — replacing a hardcoded list of four filenames.

4. Wave 1 — Sun off zenith, and object scaling

Two workstreams in parallel on disjoint files.

The aperture cosine bug

Ray power was computed as dni × aperture_area / N. DNI is defined per unit area normal to the beam, so this is only correct when the aperture faces the sun. The moment anyone tilted the sun, total power would be overstated by 1/cos θ — silently. Every existing scene has the sun at zenith and the aperture normal at +Z, so the cosine is exactly 1.0 and the goldens were unaffected bit-for-bit.

A flaw in my own test specification

I specified an end-to-end check with the aperture auto-fitted to the sun. But auto_fit makes the cosine equal 1 by construction — the test could not distinguish a correct cosine factor from a missing one. It would have passed either way.

The agent caught this, added a second case with a fixed horizontal aperture struck obliquely, then falsified it: it neutered the cosine in the tracer and confirmed the test fails — power stuck at 999 W across all elevations, wrong by +286% at 15°. Then restored the file and diffed against a backup to confirm byte-identity.

The tolerance was derived from binomial counting statistics rather than guessed: 1% is roughly 11σ — loose enough never to flake, far tighter than the error a wrong cosine produces.

Sun angles and the pole

Azimuth/elevation added with +Z as zenith and azimuth as a compass bearing from +Y (North) toward +X (East) — matching the existing box-receiver wall naming rather than inventing a convention. cos(90°) evaluates to ~6.1×10⁻¹⁷ in double, not zero, so the pole is snapped below a 10⁻¹² threshold to keep direction_from_angles({any, 90°}) exactly (0,0,−1) — the invariant the goldens rest on.

Scaling

The highest-value change was not the scale factories but nine relativized degeneracy epsilons. The worst was the triangle-intersection guard: the tested quantity scales with triangle size and with local ray-direction length, so an absolute 10⁻⁶ threshold silently dropped 1 mm triangles at 100× scale. No crash — just missing geometry and quietly wrong flux.

The test was proven to have teeth

The agent reverted the guard to its old absolute form and demonstrated the failure: the entire mesh vanishes at scale 1000. Then restored it. A passing test that would pass anyway is worth nothing.

Eight per-class world_bounds() implementations were also replaced by one non-virtual base implementation over a new local_bounds(), verified bit-identical for all eight classes under a rotated, translated, non-uniformly scaled transform.

Audit A1 — independent review

A fresh agent read the combined diff cold, with no access to either implementer's reasoning. It found a genuine high-severity bug:

decompose_trs returned wrong angles at pitch = −90°

A dropped sign factor meant the gimbal-lock branch recovered −(a−c) instead of (a−c) — while still reporting success. Reproduced with a probe: recomposition error 2.34 versus 1.18×10⁻¹⁶ for the correct pole.

The existing test only exercised non-pole angles, so it passed vacuously. Real-world trigger: any panel rotated to face along −X, which this project's radial panel arrays produce routinely. Neither implementer would have found it — the same agent wrote both the code and the test that failed to catch it.

The audit also confirmed what was sound, which matters as much: the cosine is exactly 1.0 bitwise (not merely within tolerance); all eight bounds refactors are byte-identical; all nine epsilons are dimensionally correct; Aperture::covers is exact, brute-forced over 200 000 random configurations with zero false results. And it corrected a false claim in the code's own comment — a shared helper described as "byte-identical" actually re-normalises an already-unit vector, differing in the last bit for ~15% of directions.

5. Wave 2 — SceneDocument, the pivot

This wave split the load-only 468-line SceneLoader.cpp into a document model, a parser, a writer and a scene builder. Everything downstream — the object editor, save, undo, AI scene validation — depends on it.

Why a document model rather than walking the live scene

Three facts make round-tripping from a built Scene lossy: box receivers expand at load into 6 or 11 named faces plus a synthesised absorber; TriangleMesh discards its source path and unit scale; and scene.name is read by nothing, so a walker would drop it on every save.

What was built

  • The frozen contract — a type model over all seven surface types, plane and box receivers with the optional battery, materials, sun, aperture, trace config. Material parameters are held as raw JSON so open-ended keys survive losslessly, including keys nobody has invented yet.
  • The parser — every loader default, requirement and alias ported exactly. A strict mode rejects unknown keys at every level, which is what later makes AI-generated scenes safe to validate.
  • The writer — the project's first C++ scene writer. Always emits sun.direction, because the loader throws without it. Emits battery keys only when explicitly authored, so derived defaults are not baked in as though the user had set them.
  • Path handling — mesh paths resolve against the scene file's own directory, so "Save As" elsewhere would silently break every reference. Rebasing handles the cross-volume case, which on Windows is a realistic user action.
  • Stable identity — 64-bit IDs on surfaces, removal, lookup, and a BVH dirty flag, since the acceleration structure holds raw pointers that must never be traversed stale.
A blocking gap caught before it shipped

A sub-agent decided sun.direction could be dropped in favour of azimuth/elevation, calling it "an intentional format change". The lead rejected that and verified why: the loader throws when the key is absent, and the angle round-trip is bitwise-exact only at the pole. Every scene written without a direction would have been unloadable, and off-zenith scenes would round-trip with perturbed ray sequences — the exact case Wave 1 exists to enable.

A lost-edit defect found across an ownership seam

Authored sun azimuth silently discarded

The parser re-derived sun angles from direction without passing a fallback azimuth. Azimuth is mathematically degenerate at the pole, so a zenith sun returned the default 180° and any authored azimuth_deg was thrown away on save and reload.

Found by the writer agent verifying across the seam into the parser's file — territory neither it nor its sub-agents owned. Fixed and pinned with a regression test.

Verification

Nothing in the suite exercised the writer at first — the green test run was not evidence for this wave's code, since the agents' verification lived in throwaway scratch harnesses. That gap is now closed by a permanent suite:

  • Structural round-trip, all 94 scenes. Parse strictly, write, parse strictly again, write again, and compare with deep equality. The pair is mutually reinforcing: a key the writer forgets shows as a diff, a key it invents throws on the second strict parse. 94/94, zero exceptions, zero diffs.
  • Physics round-trip. Load, save, reload, trace both — receiver power reproduces bit-identically at 17 significant digits across an analytic scene, a flat-plate scene, an STL mesh scene and an 11-face battery scene. Three of the four independently reproduce the golden baselines, which cross-validates the harness itself.
  • Box receivers keep all 6 or 11 faces with the expected names, and authored battery extents survive rather than silently falling back to derived values.
  • Mesh surfaces round-trip as a path plus a unit scale, never a vertex dump.

A second vacuous test was found and deleted in the process — it built a JSON object, dumped it, re-parsed and compared strings, testing the JSON library against itself without ever calling the loader.

6. Orchestration: what worked and what failed

The work ran as a two-layer agent hierarchy: a commander doing recon, composition and verification; Opus leads owning workstreams; Sonnet sub-agents doing bounded implementation.

What worked

  • Sequential waves with disjoint file ownership. Two workstreams edited the codebase simultaneously for an entire wave with zero conflicts. Both agents even observed each other's transient build breakage, correctly identified it as the other's in-flight work, and took no action.
  • Independent audits. Every significant defect in this project was found by an agent that did not write the code. Implementers verify their own assumptions; they cannot verify the ones they never questioned.
  • Golden baselines as a gate. Four numbers that must not move turned "did I break the physics?" from a judgement call into a test.
  • Refusing to self-certify. Every completion claim had to cite build output and named tests.

What failed

Layer-1 leads reported before their sub-agents finished

The agent tool spawns sub-agents in the background by default, so a lead has nothing to block on and returns immediately — reporting, honestly enough, "my sub-agents are running, I'll verify when they report." But its turn is over.

I misread this as the children being dead and dispatched replacements. That was wrong. The children were merely slower than their parents, and delivered good work afterwards — which made my replacements duplicate owners of the same files. I stopped both; one was mid-edit when killed, so the file had to be verified compiling, linking and passing all tests before it could be trusted.

The real defect was narrower than I first said: the leads' reporting was broken, not their delegation. The fix is to make leads block on their children, not to abandon the two-layer pattern.

Trust the diff, never the report

One lead reported its sub-agents were "actively writing" a file that was still a one-line stub on disk. Had that been taken at face value, the wave would have "completed" with core files never written, surfacing later as unattributable link errors.

Cross-referencing git diff --stat against every report is the only thing that catches this. It caught it three times.

A stale escalation, checked rather than acted on

An agent reported that scale and matrix keys were write-only and would silently corrupt geometry — a serious claim. It had read the scene loader before the refactor landed. Rather than take either side on faith, the claim was settled with a test: a unit plane scaled by (3,5) loads spanning x∈[−3,3], y∈[−5,5] through the real load path. The finding was stale; the test is permanent.

9. Open items

From Wave 2 — carried into Wave 3

  • A live trap for the Save-As UI. The plain save function cannot relocate a mesh scene: its signature has nowhere to put the original directory, so the mesh-path rebase is a documented no-op. Wiring Save-As to it would silently write unloadable files for every mesh scene. A sibling function takes the original directory and does the rebase properly. This is now pinned by a test that fails if the behaviour changes in either direction.
  • The writer emits only the sunshape parameter matching the active type, so an authored but inactive one is dropped on the first save. No shipped scene is affected.
  • A legacy validation check on receiver top-mode was dropped rather than modify the frozen contract. No scene exercises it, but it is a real capability lost.
  • One example scene widely assumed to be a box receiver is not — it has no receiver type key and takes the plane branch. Recorded so it is not used as a box fixture again.

Carried from Audit A1

  • A below-horizon sun is accepted silently — a fixed aperture yields 0 W with no diagnostic, and auto-fit will cheerfully light the cooker from underground.
  • Parameter setters change bounds with no BVH-invalidation hook.
  • Two surfaces return an inverted bounding box for negative focal length.
  • Downstream Python efficiency formulas assume the cosine is 1, and become wrong by 1/cos once it is reachable from JSON.
  • A stale comment claiming byte-identical arithmetic that is not.

10. Lessons

  1. Record a baseline before touching physics. Four measured numbers converted every subsequent "did this break anything?" from judgement into a test — across a rewritten power formula, scaling on every surface type, and a wholesale loader replacement.
  2. Have someone else check the work. Every high-severity defect here was found by an agent that had not written the code. The implementer verifies the assumptions they thought to question.
  3. Make tests fail on purpose. Three separate times a test was proven to have teeth by deliberately reverting the fix and confirming the failure. Two of those tests would otherwise have passed vacuously.
  4. Verify claims in both directions. One escalated "serious bug" was stale information; one dismissed detail was a genuine data-loss defect. Neither could be resolved by reading the report.
  5. The artefact is the truth. Reports describe intent. git diff describes what happened. They differed three times in this project.
